# Система памяти — почему агент помнит тебя через рестарты

Без памяти каждый рестарт = агент-амнезик. Здесь — схема из трёх слоёв, на которой наша
система прожила полгода. Скопируй шаблоны, наполняй своим.

## Слой 1. Стартовые правила — `CLAUDE.md` (грузится КАЖДЫЙ старт)

Файл в корне домашней директории (или проекта). Это «прошивка»: правила, которые агент
видит в начале любой сессии, до всякой памяти. Сюда — только то, что должно работать ВСЕГДА:

- правила безопасности («секреты никогда через чат»);
- правила доставки («ответ владельцу — только через reply-инструмент, текст в терминале
  до него не доходит»);
- карту проекта и точки входа.

Шаблон: [CLAUDE.md.template](CLAUDE.md.template)

## Слой 2. Файловая память — `memory/` + `MEMORY.md` (индекс)

Каждый факт — отдельный `.md`-файл с frontmatter. `MEMORY.md` — оглавление в одну строку
на факт, оно подгружается в контекст; сами файлы агент читает по мере надобности.

Четыре типа записей:
| Тип | Что хранит | Пример |
|---|---|---|
| `user` | кто владелец: роль, стиль, предпочтения | «прямой стиль, русский, объяснять термины» |
| `feedback` | как владелец просил работать (с ПРИЧИНОЙ) | «спрашивать неясное до старта — экономит токены» |
| `project` | состояние дел, невыводимое из кода | «вектор-поиск: гипотеза доказана, ждёт решения» |
| `reference` | ссылки на внешнее | «дашборд метрик: URL» |

Правила, выстраданные практикой:
- **одна запись = один факт** (не свалка);
- **у feedback всегда «почему» и «как применять»** — без этого правило мертвеет;
- связи между записями — `[[имя-другой-записи]]`;
- устаревшее — удалять или помечать датой: память это снимок, не вечная истина;
- перед записью — проверь, нет ли уже файла про это: обновляй, не плоди дубли.

Шаблоны: [memory-examples/](memory-examples/)

## Слой 3. Долгая история — claude-mem (опционально, сторонний плагин)

Плагин [claude-mem](https://github.com/thedotmack/claude-mem) автоматически сжимает каждую
сессию в наблюдения и даёт поиск по месяцам работы («как мы чинили X в июне?»). Ставится
поверх, слоёв 1-2 не заменяет: там — курируемые факты, тут — сырой архив всего.

## Как слои работают вместе при рестарте

1. Старт сессии → грузится CLAUDE.md (правила) + MEMORY.md (индекс фактов).
2. Агент по задаче читает нужные memory/*.md.
3. Продолжение прерванного разговора — `--resume <session_id>` в старт-скрипте
   (см. core/start-claude-telegram.sh): агент возвращается в ТУ ЖЕ беседу.
4. Финал значимой работы → агент дописывает/обновляет память. Круг замкнулся.
